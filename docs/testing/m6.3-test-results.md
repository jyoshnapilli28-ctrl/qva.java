# M6.3 test results

## Final build

The verified build used Java 17.0.21, Maven 3.9.9, Node 24.22.1, npm 11.9.0, Vite 6.4.6 and Linux Chrome Headless Shell 131.0.6778.33. Backend and browser tests used disposable SQLite fixtures and loopback. The tested vault used native P-256 with default browser features. The no-opt-in frontend build also compiled, and the resulting entry bundle omitted the vault controls.

| Test | Result |
| --- | --- |
| Full Java suite, including M6.2 identity | 74 passed, zero failures, errors, or skips |
| Frontend Vitest | 10 passed, including five vault format and Web Crypto tests |
| Packaged workspace browser tests | Eight operations and session tests passed |
| Packaged messaging lifecycle | One existing synthetic direct/group regression passed |
| Packaged vault browser | One multi-step scenario passed. It covered setup and confirmation mismatch, manual and inactivity lock, simultaneous tab exclusion, wrong-password retry, refresh, cross-tab logout, browser and server restarts, verified persistence and session replacement. |
| Database migration | V6-to-V7 and restart passed on an isolated file. The synthetic messaging rehearsal also passed upgrade from V5 to V7. V1–V7 were unchanged. |

The new browser scenario captured request URLs, headers and bodies and scanned them, browser console, persisted storage records, SQLite and WAL, and application logs for the generated test passphrase, PBKDF2 key material, and P-256 secret material (PKCS#8 and raw scalar, including tested encodings). None were found in the sampled data. The IndexedDB inspection verified the record fields and successful decryption with the synthetic passphrase. No runtime secret is included in the evidence. These checks sample the exercised traffic and buffers and do not prove that browser/OS internals never retain a copy.

An earlier Ed25519 prototype failed in Chrome 131 with native Ed25519 unsupported. Chromium 156 could not launch because the environment denied its singleton socket. The packaged pass applies to the final native P-256 vault, not to either failed configuration. Windows, signed distribution, OpenMLS Wasm and live MLS interoperability were not run.

## Reproduce

Use a disposable workspace. The two inherited Java audit tests expect a disposable fixture at release/Server/data/chat.db. This run used the earlier synthetic audit fixture there in an isolated copy. Do not place a production database at that path. The local sandbox required the existing Byte Buddy agent for Java tests.

    VITE_QVA_LOCAL_VAULT=1 VITE_QVA_VAULT_IDLE_MS=10000 mvn -Pqva-web package
    cd frontend
    npm run test:components
    npm test -- operations.spec.ts session.spec.ts --reporter=list
    npm test -- messaging-lifecycle.spec.ts --reporter=list
    cd ..
    python tools/test-vault-packaged.py --java /path/to/java17 --candidate-jar target/private-chat-server.jar
    python tools/test-device-identity-restart.py --java /path/to/java17 --previous-jar /path/to/v6.jar --candidate-jar target/private-chat-server.jar

The two existing browser test commands require their standard synthetic fixture variables. The new Python script creates its own runtime credentials, approved device and disposable file. It needs the short idle build policy above and uses QVA_CHROMIUM_PATH if assigned. Set QVA_SCREENSHOT_DIR to a separate directory to record the unlocked test screen. The runtime probe and sanitized build/test outputs are in the checkpoint evidence.
