# M6.3 key management

- Use a unique passphrase of at least 15 characters. The application cannot enforce that it differs from the account password without handling account secrets. Account login stays independent.
- The Worker isolates routine cryptographic operations from React state. The derived AES key is a non-extractable Web Crypto CryptoKey, and the unlocked signing key is retained only in the worker. Temporary plaintext buffers are cleared where practical. JavaScript strings, browser internals, garbage collection, swap and platform copies cannot be reliably zeroized by the app.
- The binary P-256 private key is exported briefly inside the Worker to create a password-encrypted backup of local state in IndexedDB. It is imported as non-extractable on unlock. The key is currently local and is never registered with Spring Boot. It does not meet the M6.2 Ed25519 registry contract and will not be promoted to an MLS identity. Device claim or proof of possession must be designed against the exact, vetted MLS integration.
- An account password reset does not recover a vault. Without its encryption passphrase or browser record, the local private key is lost. A future explicit replacement flow should register a new version and require re-verification. This slice has no reset button and avoids overwriting existing records.
- Browser clear-data, origin changes, restoring an earlier profile or device loss can remove or roll back local records. Server backups do not contain the local record or its secret. External OS/browser backup behavior is outside QVA. This milestone implements no recovery derivation, backup sync, or administrative escrow.
