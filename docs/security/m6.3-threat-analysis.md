# M6.3 threat analysis

| Threat | Controls and residual exposure |
| --- | --- |
| Stolen IndexedDB record | GCM authentication and password-derived encryption. Offline password guessing remains possible. PBKDF2 is computationally expensive but does not have Argon2id's memory-hardness. |
| Altered header or record | Fixed format allowlist and size limits before KDF, authenticated associated data and tag verification, record preserved on failure. The browser can still delete or roll back a vault. |
| Untrusted browser code or malicious HOST | Existing /app/ code comes from HOST. A HOST capable of replacing it can read entered passwords, arrange malicious worker code and access plaintext. The lab build opt-in is not code integrity. HTTPS protects transport and secure context, not HOST trust. |
| Compromised device | A trusted local browser can access active secrets. Non-extractability and worker teardown constrain routine application code. They provide no guarantee against compromised extensions, OS, browser, unlocked debugging, or malicious application updates. |
| Session/approval loss | The vault locks when loss is detected by workspace checks. A visible workspace polls approximately every 15 seconds, with additional live reconciliation. Background scheduling or connectivity can delay observations. A logout attempt locks locally before the request returns, and broadcasts to cooperating tabs. |
| Cross-tab persistence and contention | Exclusive per-device Web Lock while using the key. Insert-only IndexedDB persistence prevents overwrite. The app has no state mutation/signing commands yet. Existing user sessions and one-login policy are unchanged. |

A malicious-HOST-resistant Windows client requires independent distribution of packaged app assets via a verified signing chain. Pin the installer trust root through an independently authenticated channel. Verify installer signatures and signed manifests covering versions, content hashes and origin. Store a monotonic accepted update version and define recovery from revoked signers or compromised releases under a separately controlled root. Keep worker/native key operations behind a narrow local interface and disallow loading executable UI code from HOST. Restrict WebView2 navigation, messaging and permissions. The Windows package, signing, update controls, rollback and key isolation have not been built or tested.
