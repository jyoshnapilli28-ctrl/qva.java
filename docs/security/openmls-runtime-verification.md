# OpenMLS runtime readiness after M6.3

Refer to the [M6.2 dependency verification](openmls-dependency-verification.md) for the published 0.9.2 requirements, license, provider comparison and advisory floors. Version 0.9.2 remains the exact candidate on the 0.9 line. Publication and upstream documentation do not establish a QVA build. Cargo/Rustup and Windows execution are unavailable in this development runtime. No crate checksum verification, QVA lockfile resolution, compiler minimum proof, Wasm compile/run, Windows execute or interop result was obtained. QVA's package lock and Java dependencies are unchanged. No OpenMLS code is installed.

## Build and interoperability gate

1. Verify the exact crate archive against registry checksum and source commit. Pin the Rust toolchain, crate/provider versions and feature set. Verify declared Rust requirements inspected in the exact crate metadata against a locked build. Screen the dependency graph and its licenses against current Rust advisories.
2. Compile to wasm32-unknown-unknown with the pinned crypto and storage providers. Prove browser randomness, clock/runtime support, data handling and worker lifecycle in the actual signed Windows runtime. Check Windows browser and native builds independently.
3. Exercise RFC vectors and interoperability against an independent MLS implementation. Confirm exact encoding of credential, public key and KeyPackage, signature and expiry validation, owner proof-of-possession, replay handling, current group epoch checks and durable ordered control records.
4. Design a new authenticated vault payload version for provider-specific private MLS state. The M6.3 local P-256 key was generated by Web Crypto and imported into a non-extractable handle. There is no demonstrated adapter between it and OpenMLS. Avoid exporting that handle or relying on unsupported keystore access. An explicit migration should establish MLS identity and reverify the new credential, or otherwise show equivalent reviewed key binding.
5. If the Wasm provider remains blocked, evaluate native OpenMLS inside an independently signed Windows application with local packaged React UI and a tightly scoped WebView2 bridge. Keep key serialization, cryptography and storage inside the trusted native runtime. Limit the bridge to necessary typed operations and opaque transport. This option also needs exact provider/toolchain validation, Windows tests, signed distribution and a separate security review.
